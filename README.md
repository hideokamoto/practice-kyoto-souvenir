# 京都いけず問答

オープンデータが出す、ちょっといけずな京都クイズ。京都市・京都府・国のオープンデータから、毎回ちがう 4 択（一部 2 択）の問題を自動で作ります。1 回 5 問。

旧「きょう再見」（京都の観光スポットとお土産の発見アプリ）を作り替えたものです。旧アプリが使っていた京都市オープンデータ「京都観光Navi」はそのまま問題の材料にしています。

## モード

難易度 3 つ（かんたん・ふつう・むずかしい）と「今日の5問」。どのモードも下の全データ・全 17 種類の問題から出します。1 回 5 問で、問題の種類はなるべく重ならないように回します。

| 材料 | 問題の種類 |
|---|---|
| 京都観光Navi お土産情報（108 品） | 名前を伏せた説明文から名前を当てる／漢字の名前の読み |
| 京都観光Navi 見もの情報（648 件） | 説明文から名前／文化財の時代／国宝か重要文化財か／地名の読み／所在の区 |
| 家計調査 都市別ランキング（395 品目） | 京都市が 52 市中 1 位の品目／京都市の順位／1 位の都市 |
| 京都府 観光施設一覧（京都市内 762 件）＋地理院タイル | 航空写真の中心にある寺社／所在の区／いちばん近い名所 |
| Wikidata（457 件）＋ Wikimedia Commons（写真 437 枚） | 写真の寺社／世界遺産「古都京都の文化財」の構成資産 |
| 国税庁・農林水産省・文化庁の都道府県別データ（8 指標） | 全国 1 位の都道府県／京都府の順位 |

「今日の5問」は「ふつう」の難しさで、日本時間の日付で決まる日替わり 5 問（同じ日なら誰でも同じ。上の 6 つの材料から 5 つを選び 1 問ずつ）。

### 難易度で変わるもの

問題の種類は全段階で同じです。変えるのは「誤答の紛らわしさ」と「題材の有名さ」です（規則は `src/app/quiz/templates/levels.spec.ts` で固定）。

| 問題 | かんたん | ふつう | むずかしい |
|---|---|---|---|
| 説明文から名前 | 誤答は別の種類（お菓子に対して工芸品など） | 誤答は同じ種類 | 同じ種類で、引用は最初の 1 文だけ |
| 読み | 誤答は文字数が 2 以上違う読み | 文字数が近い読みから | 文字数の差が 1 以内、頭の文字が同じ読みを優先 |
| 文化財の時代 | 誤答は 2 時代以上離れた時代 | 近い 4 時代から 3 つ | いちばん近い 3 時代 |
| 何区？ | 誤答は中心が遠い区 | ランダム | 中心が近い区（区の中心は観光施設の座標の平均） |
| 京都市が 1 位の品目 | 誤答は京都市が下位 4 分の 1 の品目 | 下半分の品目 | 京都市が 2〜5 位の品目 |
| 京都市の順位 | 上半分か下半分の 2 択 | 4 つの順位帯 | 順位そのもの（誤答は前後 3 位以内） |
| 航空写真 | 誤答は 5km 以上離れた施設 | 1.5km 以上 | 1.5〜4km の近所 |
| いちばん近い名所 | 誤答は正解の 3 倍以上遠い | 1.6 倍以上遠い | 1.6 倍以上だが 3km（か 2.5 倍）以内 |
| 写真の寺社 | 有名な寺社だけ（Wikipedia などの記事がある言語版が 10 以上） | 3 以上 | 全部。誤答も 3km 以内の近所 |
| 世界遺産の構成資産 | 誤答は無名な寺社（言語版 3 以下） | どれでも | 有名な寺社（言語版 10 以上） |
| 全国 1 位の都道府県 | 誤答は下位の都道府県 | 2〜7 位と京都府 | 2〜4 位 |
| 京都府の順位 | 誤答は 5 位以上離れた順位 | 前後 4 位以内 | 前後 2 位以内 |

国宝か重要文化財か（2 択）と「1 位の都市」は、どの段階でも同じ作り方です。

## 問題を作るときの決まり

自動生成なので、正解が 2 つある問題や答えが見えている問題を作らないことを、テストで保証しています（`src/app/quiz/real-data.spec.ts` が全データ・全テンプレートで確かめます）。

- 問題文・引用・画像の代替テキストに正解が出ていれば、その問題は作らない（カタカナ／ひらがな、小書きの違いも同じとみなす）。
- 選択肢は表記ゆれも含めて重複させない。
- 同じ対象（例: 清水寺 本堂）は、テンプレートが違っても 1 プレイで 1 回だけ。
- 名所の時代と指定は、説明文の最初の一文の定型句（「〜にある桃山時代建築の国宝建造物」）からだけ取る。一文に時代が 2 つあれば使わない。
- 美術品は寄託先（京都国立博物館など）の住所が入っていることがあるので、区を問うのは建造物・名木・地名など場所そのものだけ。
- 航空写真の誤答は正解から 1.5km 以上、寺社の写真の誤答は 0.5km 以上離れたものだけ（同じ境内の塔頭などで正解が 2 つにならないように）。
- 「いちばん近い名所」は、正解が他の選択肢より 1.6 倍以上近いときだけ出す。起点も選択肢も寺社などの名所に限る（観光施設の「何区？」も同じ）。
- 説明文に名前が出てこず伏せ字が無いときは、「〇〇に当てはまる」ではなく「説明されている〜は？」と聞く。
- 難易度ごとに、全 17 種類の問題がそれぞれ 8 件以上の対象を持ち、半分以上の対象で問題を作れること、続けて 10 回遊んでも同じ問題が 50 問中 5 問以下であることをテストで確かめる。
- 世界遺産の誤答は「構成資産ではない」と確定しているものだけ（構成資産の一覧が 17 件そろったときだけ判定し、構成資産から 500m 以内の寺社は判定しない）。
- 順位の問題は、同じ値の都道府県・都市があって順位が決まらないものは出さない。
- Wikidata の創建年は検証できないため、出題に使わない。

## 開発

Node.js 24 以上が必要です（Angular 22）。

```bash
npm ci
npm start                 # http://localhost:4200/
npm test                  # 単体テスト（Angular / Vitest）＋データ生成のテスト（node:test）
npm run build             # 本番ビルド（dist/kyoto-ikezu-quiz/browser、base href は ./）
npx playwright test       # E2E（ビルド成果物を games.hidetaka.dev と同じ CSP で配信して全モードを遊ぶ）
```

E2E は `npm run build` の後に実行します。ブラウザを別途用意している環境では `PW_CHROMIUM_PATH=/path/to/chrome npx playwright test` で指定できます。

### 構成

```
src/app/
  data/            データの型（types.ts）、読み込み（data.service.ts）、地理院タイルの出典
  quiz/            出題エンジン
    templates/     データごとの出題テンプレート（*.spec.ts にフィクスチャのテスト）
    game.ts        モード定義・1 プレイの組み立て・今日の5問・称号
    real-data.spec.ts  生成済みデータ全体に対する性質テスト
  pages/           ホーム・出題・結果・クレジット・ライセンス
  shared/          航空写真（地理院タイル）・Commons の写真・出典リスト
public/data/       生成済みのデータ（手で編集しない）
tools/data-build/  データ生成スクリプトと、その入力（raw/）・テスト
e2e/               Playwright の E2E
```

### データの作り直し

`public/data/*.json` は `tools/data-build/` のスクリプトが `raw/` の原資料から作ります。実行時にアプリが外部の API を叩くことはありません（画像のタイルと写真を除く）。

```bash
npm run data:navi     # 京都観光Navi → meisho.json / omiyage.json
npm run data:kanko    # 京都府 観光施設一覧 → kanko.json
npm run data:kakei    # 家計調査ランキング（xlsx）→ kakei.json
npm run data:shaji    # Wikidata + Commons → shaji.json（キャッシュを使う。取り直しは -- --refresh）
npm run data:sangyo   # 国税庁・農林水産省・文化庁 → sangyo.json
```

作り直したら `npm test` を実行してください。`real-data.spec.ts` が、全テンプレートの問題が壊れていないことを確かめます。

動作確認の録画とスクリーンショットは `node tools/demo/record.mjs [URL]` で撮れます（全 4 モードを 5 問ずつ遊び、`demo-out/` に動画と画像を出力。URL の既定は Netlify のデプロイプレビュー）。

OGP 画像は `node tools/og/make-og.mjs` で `tools/og/og-image.html` から撮り直せます。

## 公開

Netlify にデプロイし、games.hidetaka.dev のドメインから配信します。

- **デプロイ:** Netlify サイト kyoto-app が `main` を自動でビルドして公開します（`netlify.toml`、Node 24 に固定）。PR ごとのデプロイプレビューも同じ設定です。
- **配信:** `https://games.hidetaka.dev/kyoto-ikezu-quiz/`。games.hidetaka.dev の CloudFront が `/kyoto-ikezu-quiz` を剥がして `kyoto-app.netlify.app` へ取りに行きます（`hideokamoto/games.hidetaka.dev` の `cdk/src/apps.ts` に登録）。ビルドは base href を `./` にしているので、Netlify の URL でもサブパスでも同じ成果物が動きます。
- **CSP:** games.hidetaka.dev の CloudFront が付けます。許可が必要な外部ホストは、画像の `upload.wikimedia.org` と `cyberjapandata.gsi.go.jp` だけです。
- **キャッシュ:** Netlify のデプロイは games.hidetaka.dev の CloudFront キャッシュを無効化しないので、反映は最大で 5 分ほど遅れます。
- GitHub Actions（`.github/workflows/ci.yml`）はテスト・ビルド・E2E だけを実行し、公開はしません。

## 既知の制約

- 京都観光Navi は 2021 年 3 月更新のデータです。国宝・重要文化財の指定などはその時点の記載によります。
- この開発環境からは upload.wikimedia.org が 429（レート制限）を返したため、寺社の写真が実際に表示されることは確認できていません。表示できなかったときは写真の枠にその旨を出します。
- 清酒の値は国税庁のアンケートに回答した製造業者の合計で、全製造業者の合計ではありません（問題文にそう書いています）。
