# 企画書: 京都いけず問答（実装済み）

作成 2026-10-25。当初は段階リリース案だったが、「フェーズを分けずに一気に TDD で作る」方針に変え、全モードを 1 回で実装した。実装の詳細は README、データの調査結果は `docs/open-data-survey.md`。

## アプリ名

**京都いけず問答**（slug: `kyoto-ikezu-quiz`）

- 「いけず」は京都ことばで「意地悪」。データから機械的に作る問題は、人が作る問題より容赦がない（「他の野菜・海藻加工品」が 1 位の品目、など）。その性格をそのまま名前にした。
- 「問答」は寺社の多い京都らしさと、1 問ずつ答えて解説が返ってくる形式を表す。
- 称号も京都ことばで揃えた（修学旅行生 → いちげんさん → まだまだ観光客 → ぶぶ漬けの意味がわかる人 → 洛中のお人 → いけず問答の免許皆伝）。
- 名前は `src/app/app-info.ts` の定数 1 か所で変えられる（index.html・OGP 画像・README は別途）。

## コンセプト

京都市・京都府・国のオープンデータから、毎回ちがう問題を自動で作る 5 問クイズ。問題は人が書かない。データが増えれば問題が増え、解説には必ず出典を出す。兄弟アプリ（Anthropic数列クイズ・京都地下鉄マニアッククイズ）と同じく games.hidetaka.dev に置く。

## モード（難易度 3 つ＋今日の5問）

| モード | 出題 |
|---|---|
| かんたん | 全データ・全 17 種類から。誤答は種類・場所・順位が離れていて、写真は有名な寺社だけ |
| ふつう | 全データ・全 17 種類から。誤答はほどほどに紛らわしい |
| むずかしい | 全データ・全 17 種類から。誤答は隣の区・近所の寺社・前後の順位・隣の時代、説明文は 1 文だけ |
| 今日の5問 | 「ふつう」で、日本時間の日付で決まる日替わり（6 データから 5 つを選んで 1 問ずつ） |

当初はデータの出どころ別に 6 モード（みやげ鑑定・名所めぐり・京都人の台所・空から当てる・寺社の写真・京の産業）＋今日の5問にしていた。これを次の理由で作り替えた。

- 遊ぶ人にとって「データの出どころ」は選ぶ理由にならない。
- 1 モードに 2〜5 種類の問題しかなく、5 問のうちに同じ種類が繰り返されて薄い。続けて 10 回遊ぶと、京の産業は 50 問中 34 問、寺社の写真は 15 問が既出の問題だった。
- 全データを混ぜ、難しさは「誤答の紛らわしさ」と「題材の有名さ」（Wikidata の sitelinks＝記事がある言語版の数）で作り分ける形にした。10 回続けて遊んだときの既出は、どの難易度でも 50 問中 5 問以下（テストで固定）。

難易度ごとの規則は README の「難易度で変わるもの」と `src/app/quiz/templates/levels.spec.ts`。

## 当初案から変えた判断

| 当初案 | 実装 | 理由 |
|---|---|---|
| Phase 1〜3 に分けて段階公開 | 全モードを一度に実装 | 依頼による |
| Ionic・NgRx・Capacitor を残すか要判断 | 外した（Angular 22 standalone + signals） | games.hidetaka.dev の CSP（`script-src 'self'`）下で実績のある兄弟アプリの構成に揃えた |
| みやげの「分類当て」 | 作らない | 分類コードの意味（工芸・名物・食）は推定で、京人形が「名物」側のコードに入るなど公式の分類名と言えない |
| 寺社の「創建がいちばん古いのは？」 | 作らない | Wikidata の創建年を一次資料で検証できない（例: 東寺が 676 年になる） |
| 清酒の「製造業者数」 | 作らない | 国税庁の表は「アンケートの回答者数」で、製造業者数ではない |
| 京野菜（みずな・えびいも）の生産順位 | 作らない | 地域特産野菜生産状況調査にこれらの品目が無い。京都府が 3 位以内に入るのは「とうがらし（辛味種）」だけ |
| DBpedia の利用 | 使わない | 2026-10-25 時点で ja.dbpedia.org の SPARQL が 502。同じ用途は Wikidata（CC0）で足りた |
| 地図問題 | 国土地理院の航空写真（ラベルなし）にした | 淡色地図などは寺社名のラベルが出て答えが分かってしまう |
| 区の問題（名所） | 建造物・名木・地名など場所そのものに限定 | 美術品は寄託先の京都国立博物館（東山区茶屋町527）の住所が入っているものがある |

## 品質の担保（TDD）

- データ生成（`tools/data-build/*.test.mjs`、node:test）: CSV/xlsx/PDF のパース、抽出規則、除外規則を先にテストで書いてから実装。原資料の値との照合（openpyxl・pdftotext の生値）も分担時に実施。
- 出題エンジン（`src/app/quiz/**/*.spec.ts`、Vitest）: テンプレートごとにフィクスチャで規則を固定し、`real-data.spec.ts` で全データ・全テンプレートを多数のシードで生成して「答え漏れなし・選択肢の重複なし・出典あり・毎回 5 問そろう」を確かめる。
- 画面（`src/app/pages/pages.spec.ts`）と E2E（`e2e/quiz.spec.ts`、Playwright）: E2E は games.hidetaka.dev と同じ CSP を付けたサーバで全 4 モードを最後まで遊び、CSP 違反が 0 件であることを確かめる。
- 生成された問題を目で読み、テストでは拾えなかった問題（美術品の区、ホテル同士の距離問題、同名寺社の並び、長すぎる注記）を見つけるたびに、先にテストを足してから直した。

## 残っている確認事項

1. 京都市オープンデータポータルの利用規約原文（ポータル停止中のため）。
2. Wikimedia Commons の写真が利用者のブラウザで表示されること（開発環境からは 429）。
3. games.hidetaka.dev への登録（別リポジトリの PR）と、このリポジトリの GitHub Pages 有効化。
